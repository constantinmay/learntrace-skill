# Task 4 逻辑树

这份文件帮助评审快速理解 Task 4，不展开内部类和字段。

## 一句话概括

Task 4 把 Task 2、Task 3 提供的可观察事实整理成学习节点候选，经学生本人
确认后，输出可阅读、可追溯的学习档案。

OpenCode Skill 负责发现范围、取得授权和调用 CLI；下图描述的是授权完成后
由 LearnTrace 本地归档流水线处理证据的过程。宿主 Agent 是链路中唯一的
LLM；CLI 本身不调用任何远程模型。

## 主流程

```text
Task 2 / Task 3 可观察事实
          |
          v
校验、去重并生成候选学习节点
          |
          v
学生确认、补充或否认候选
          |
          v
Markdown 学习档案 + archive JSON + 待确认问题
```

## 1. 输入

- Task 2：Git、文档和已有测试日志形成的事实。
- Task 3：学生逐个授权后产生的一个或多个最小化 OpenCode 会话轨迹。
- 可选的解析告警和学生确认文件。

输入只描述发生了什么，不证明作者身份、个人理解或 AI 与提交之间的因果
关系。

## 2. 候选生成

- 使用可重复的本地确定性规则；CLI 不调用远程 LLM。
- 更深入的语义理解由宿主 Agent 承担，而不是由 CLI 完成。
- 每个候选都必须引用真实的 `basis_event_ids`，并带有不确定性和面向学生
  的确认问题。
- 只有工具名称、命令类型或文件路径的低信息轨迹，不单独生成学习节点。

## 3. 学生确认

- 首次分析保存事实和候选快照。
- 学生可以确认、补充或否认候选。
- 学生原话与系统候选分开保存。
- 确认阶段只读取快照，不重新解析，也不再次推断候选。

## 4. 输出

- `learning-record.md`：面向学生和评审的学习档案。
- `.learntrace/archive-records.json`：事实、候选、确认、告警、来源索引和稳定
  内容指纹。
- `.learntrace/learning-questions.md`：尚待学生回答的问题。

Markdown 正文展示项目目标、项目进展、学习线索、AI 协作概况、学生反思和
后续学习问题；事件 ID、候选 ID、直接依据和来源信息放入折叠的机器审计附录。
完整事实和来源索引同时保留在机器档案中。没有测试日志时，报告会明确说明
当前证据不能证明测试已经运行或通过。没有形成候选时，问题文件仍会提出证据
缺口和反思问题，但不会把这些问题伪装成学习结论。

## 5. 信任和安全边界

- 候选推断不能直接写成事实。
- 不执行目标仓库代码、测试或日志里的命令。
- 不做作弊判断、作者归因、贡献排名或自动评分。
- 不编造学生回答、确认时间、反思或缺失证据。
- CLI 本地运行，无出站网络；源码、备注和 `source_refs` 不离开本机。
- 机器档案可能含本地来源路径，分享前只检查并导出 Markdown。

## 评审检查清单

- 候选是否引用真实事实，而不是只靠时间邻近或工具名称？
- 学生确认是否与系统推断分开保存？
- 确认阶段是否复用首次快照？
- Markdown 是否可读，并明确指出缺失的测试证据？
- 离线环境（不调用任何远程模型）下是否仍然可重复运行和审计？
