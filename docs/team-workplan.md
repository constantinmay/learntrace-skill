# M1 四人分工草案

## M1 目标

完成一条可信学习节点的端到端闭环：Python 脚本从本地项目材料中整理可观察事实，OpenCode Skill 基于证据提出候选学习节点，经学生确认、补充或否认后，生成本地 Markdown 学习档案。

M1 不执行用户代码，不将候选推断写成事实。首个轨迹适配器只支持 OpenCode；其他 Agent 适配为自主扩展，不阻塞 M1。

## 共同前置任务

四人先共同冻结 `schema v0` 的公共骨架：

- `schema_version`
- 记录 `id`
- 可多项的 `source_ref`
- 证据等级
- 候选状态
- 缺失状态

同时准备手工 JSON 样例，供各任务线并行开发和中段联调使用。

## M1 共同验收

1. 对固定样例可从输入跑到本地学习档案。
2. 每条可观察事实均可回溯到文件、提交、日志或轨迹记录。
3. 系统候选推断带依据和不确定性，未经学生确认不得成为学习结论。
4. 证据或轨迹缺失时标记“未记录”，不推断 AI 协作。
5. 不执行仓库代码，也不重放日志或轨迹中的命令。

## 协作规则

1. 四人共同冻结 `schema v0`，共同验收 M1。
2. 团队成员在原仓库建立短分支并通过 PR 合并，禁止直接推送 `main`。
3. 一项任务对应一个 Issue 和一个 PR；接口变化或阻塞在 Issue/PR 中记录后再讨论。
4. 公开仓库只提交脱敏样例，不提交密钥、个人信息、真实学生材料或原始 AI 轨迹。
5. M1 截止日期：八月初
