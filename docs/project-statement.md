# 项目陈述书：AI 协作学习档案 Skill

## 一句话概述

面向 AI 辅助课程项目的 Skill：把 AI 交互轨迹、Git 提交和项目材料整理为可追溯的学习档案，帮助学生光明正大地说明 AI 如何协助项目、自己如何决策、修正和学习。

## 背景与目标

在 AI 时代，学生使用 AI 辅助完成作业和项目不可避免。项目不应把 AI 使用视作需要隐藏或被审查的行为，而应帮助学生保留和整理协作过程，将其转化为能够复盘、分享和用于答辩的学习证据。

系统不判定作弊、不做 AI 作者归因、不对理解程度给分。它只展示可观察的协作与学习证据，并让学生确认和补充自己的反思；系统推断不会被写成既成事实。

## MVP 输入与范围

- 用户：使用 AI 完成课程项目的学生。
- 项目范围：首版支持本地编程项目，不限定具体编程语言。
- 必需输入：本地 Git 仓库、任务书、项目报告、既有测试日志。
- 文档格式：UTF-8 Markdown 或纯文本。
- AI 轨迹：用户提供时生成 AI 协作学习档案；未提供时降级生成普通项目学习复盘，不推断 AI 协作。
- 可选输入：覆盖率或 CI 导出、Issue/PR 导出、运行日志。

系统自动发现候选文件，用户确认本次分析范围。项目主张和候选学习节点由系统自动提取。

## 核心流程

1. 解析仓库、任务书、报告、测试日志和可选的 AI 轨迹。
2. 提取项目进展和 AI 协作中的可观察事件。
3. 基于事件生成候选学习节点，例如追问、修改或拒绝 AI 建议、修复失败方案、补充测试和调整设计约束。
4. 由宿主 Agent 基于整理结果向学生提出少量问题，学生确认、补充或否认候选学习节点。
5. 生成可编辑的学习档案：项目目标、AI 使用场景、关键决策、验证证据、个人反思和后续学习计划。

Git 只按语义模块展示成员在版本历史中提交和维护过的内容，不用于推断 AI 会话与提交的对应关系，也不用于给个人贡献打分。首版不运行用户仓库中的测试，只解析已有测试证据。

## 证据等级与反幻觉约束

学习档案中的每条内容必须标注为以下三类之一：

- 可观察事实：可直接引用到 Git、文档、测试日志或经授权的轨迹记录。
- 学生确认：由学生对候选学习节点作出的确认、补充或否认。
- 系统候选推断：系统根据已有材料提出的可能解释，必须标明依据和不确定性，未经学生确认不得作为学习结论展示。

证据不足时，系统只提出问题或标注“未记录”，不补全事件、不推断 AI 使用情况，也不把提交记录解释为个人作者身份。

## Skill 与脚本边界

- MVP 完整交付为可安装 Skill 与随附 Python 解析脚本，以 OpenCode 为首个验证宿主，并为 Claude Code 预留第二适配器。
- Python 只负责脚本解析：仓库、Git、测试日志、文档和轨迹的读取与结构化输出。
- 宿主 Agent 负责理解、整理学习节点和与学生的对话追问。
- 后续可在同一脚本层外增加独立 Agent，但它不属于 MVP。

## 轨迹与隐私

OpenCode 和 Claude Code 的轨迹适配器各自转换为统一的 `trace.json`。默认只保留最小协作证据：时间、工具类型、文件路径、命令摘要和来源宿主。完整聊天内容仅在学生显式授权时读取或引用。

学习档案默认保存在学生本地；学生可手动导出脱敏分享版给教师或用于答辩。MVP 不做在线上传、教师后台或自动提交。

## 样本与评测

- 使用团队既有 AI 协作项目检验真实但可能不完整的输入。
- 使用人工构造示例项目和轨迹验证关键事件、学习节点和报告生成是否正确。
- 首轮评测关注：协作过程是否被如实整理、候选学习节点是否合理、学生是否能据此完成项目复盘和说明。

## 明确不做

- 作弊检测、作者归因、贡献排名或学习程度分数。
- 自动评分、模拟教师评判或预测答辩结果。
- 执行不可信仓库代码、接入校内私有系统、构建 Web 平台。
- 首版支持所有语言、所有文档格式或所有 AI 编码 Agent。
- 多人协作的团队总览、成员学习卡和个人轨迹汇总。

- 多人协作项目的成员轨迹汇总与团队报告。
